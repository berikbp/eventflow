- [x] Повтор запроса с тем же email/ключом не занимает второе место.
- [x] Дубликат email с другим ключом не раскрывает доступ к существующей записи.

- [ ] Билет и email-подтверждение (Phase 4–5).

- [x] При заполнении — FIFO waiting list по монотонному порядку регистрации.

## Билеты и check-in
- [ ] Уникальный непредсказуемый код, просмотр билета.
- [ ] Проверка организатором и форма ввода кода.
- [ ] Один check-in; повторный запрос не увеличивает посещаемость.
- [ ] Отменённый билет недействителен; QR не обязателен.

## Dashboard и real-time
- [ ] Подтверждённые, ожидающие, check-in, вместимость, статусы участников.
- [ ] Обновление без перезагрузки после регистрации, отмены, check-in, переноса.
- [ ] SSE (либо обоснованный WebSocket), минимум два клиента.
- [ ] Восстановление актуального состояния после reconnect.

## Уведомления и переносы
- [ ] Подтверждение регистрации с билетом.
- [ ] Продвижение из очереди с билетом.
- [ ] Одно логическое напоминание за 24 часа соответствующим участникам.
- [ ] Уведомление зарегистрированным при переносе.
- [ ] Фоновая отправка без блокирования HTTP.
- [ ] Задания переживают restart; повторная обработка не дублирует логические письма.
- [ ] Transactional outbox, уникальные ключи уведомлений, retries.
- [ ] Гарантии создания уведомления отделены от SMTP delivery; без ложного exactly-once.
- [ ] При переносе дата сохраняется, SSE обновляется, напоминания пересчитываются.
- [ ] Старые задания не отправляют неверные письма.
- [ ] Поведение при времени до события менее 24 часов описано и протестировано.
